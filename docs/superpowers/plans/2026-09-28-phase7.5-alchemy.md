# Phase 7.5 Implementation Plan — Alchemy UI, model choice, Photoreal Lab

> **For agentic workers:** executed inline (superpowers:executing-plans) by the
> session that wrote it. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Restyle the whole app in the approved "Alchemy" direction, add a
per-message model switcher, and add an admin Lab that benchmarks settings and
adopts the winners as per-model defaults.

**Architecture:** Server-side, profiles overlay the registry's checkpoint
defaults. The policy honours a pinned checkpoint, with three explained
exceptions. The queue gains a preemptible low-priority lane for Lab jobs.
Client-side, `app.js` and `styles.css` are rewritten in place (same helpers,
same state model), and there is a new `lab.html` with `lab.js`.

**Tech stack:** FastAPI, SQLite, vanilla JS with no build step, Pillow, and
self-hosted Sora and JetBrains Mono woff2 fonts.

**Spec:** `docs/superpowers/specs/2026-09-28-alchemy-ui-models-lab-design.md`

## Global constraints

- No CDN at runtime: fonts are self-hosted, and there are no new JS
  dependencies.
- Port 8188 is never exposed. Every image is served from app-owned storage.
- Every row is scoped to its owner. Lab routes are admin-only, and anyone else
  gets a 404.
- Nothing machine-specific is committed. Tuned profiles live in the DB, and
  `registry.json` stays the baseline.
- Gate every commit on pytest's real exit code, with ruff clean. Commit
  trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- The boot path of every page is executed in the test suite (node DOM shim).

### Task 1: Schema, migrations, palette

**Files:** `alchemyui/schema.sql`, `alchemyui/db.py`, `alchemyui/storage.py`,
`alchemyui/queue.py`, `alchemyui/jobs.py`, `tests/test_db.py`,
`tests/test_palette.py`

**Produces:**
- The migrations listed in the spec, plus new tables `model_profiles`,
  `lab_runs` and `lab_cells`.
- `storage.palette_of(data: bytes) -> list[str]`: three `#rrggbb` colours,
  vivid first, never raising (it returns `[]` for bytes that are not an
  image).
- `QueueManager._collect` stores `palette` and `lab_run_id` on image rows.
- `image_public` exposes `palette`, and `lab_run_id` only when it is set.
- `backfill_palettes(db)`: an async startup task that fills rows with a NULL
  palette whose file exists, in batches.

**Tests:** migrating an old DB adds every column; the palette of a two-colour
PNG contains both colours; garbage bytes give `[]`; a completed job's image row
has a palette; the backfill fills existing rows.

### Task 2: Registry taglines, overrides, profiles

**Files:** `alchemyui/registry.py`, `workflows/registry.json`,
`alchemyui/profiles.py`, `tests/test_profiles.py`

**Produces:**
- `CheckpointInfo.tagline: str`.
- `Registry.switchable() -> list[CheckpointInfo]`: `photoreal`, family in
  `sdxl`/`sd15`, ordered quality, then fast, then draft.
- `Registry.set_override(name, settings | None)` keeps the base and replaces
  the CheckpointInfo with merged defaults. `Registry.base(name)` returns the
  untouched entry.
- `profiles.PROFILE_KEYS = ("steps", "cfg", "sampler", "scheduler", "look",
  "negative")`.
- `profiles.validate(settings, reg) -> dict` raises `ProfileInvalid`. It
  clamps steps to 1–80 and cfg to 1–15, checks sampler and scheduler against
  the txt2img workflow's choices, and trims text to 400 characters.
- `async load_profiles(db, reg)`, `async save_profile(db, reg, name,
  settings, user_id, cover_image_id=None)` and `async reset_profile(db, reg,
  name)`.
- `profiles.compose(prompt, negative_extra, ck, house_negative) -> (prompt,
  negative)`.

**Tests:** an override changes `resolve()`'s steps and cfg; a reset restores
them; invalid samplers are refused; `compose` appends the look and prefers the
profile's negative over the house one.

### Task 3: Policy pins

**Files:** `alchemyui/planner/policy.py`, `tests/test_policy.py`

**Produces:**

**Tests:** generate and transform use the pin; extend ignores it (with a note);

### Task 4: Turns carry the pin; models API; thread covers

**Files:** `alchemyui/threads.py`, `alchemyui/chat.py`, `alchemyui/app.py`,
`tests/test_chat_api.py`, `tests/test_threads.py`, `tests/test_models_api.py`

**Produces:**
- `create_turn(..., model=None)` validates against `reg.switchable()`
  (`TurnError`, 400) and stores the pin on the turn and the thread.
- `_execute` passes `pinned=row["model"]`.
- `turn_public` gains `pin` and `note`. `_thread_public` gains `model` and
  `cover_url` (the latest image of the thread).
- `GET /api/models` returns `{models: [{name, label, tagline, family,
  resident, eta_s, cover_url}], resident}`.
- `GET /api/models/cover?name=` serves the adopted cover (a lab image) to any
  signed-in user, and is a 404 otherwise.

**Tests:** a pinned turn submits jobs with that checkpoint; an unknown model is
a 400; the thread reports its model and cover; `/api/models` lists four models
with ETAs, and marks the resident one.

### Task 5: Queue lanes and preemption

**Files:** `alchemyui/queue.py`, `tests/test_queue.py`

**Produces:**
- `Job.lane` (`"user"`/`"lab"`), `Job.lab_run_id` and `Job.preempted`, all
  persisted.
- `submit(..., lane="user", lab_run_id=None)` inserts user jobs before the
  first lab job.
- `_pick_next` only groups runs within one lane.
- A user submit while a lab job runs sets `preempted`, sets its cancel event
  and interrupts it.
- Reconcile restores user jobs first.
- The snapshot's `depth` and positions count user jobs only, plus a new
  `lab_depth`.

**Tests:** a user job jumps queued lab jobs; a lab job never overtakes a user
job; preemption interrupts the running lab job and marks it cancelled and
preempted; depth excludes lab jobs; a restart keeps lane order.

### Task 6: The Lab backend

**Files:** `workflows/lab.json`, `alchemyui/lab.py`, `alchemyui/lab_api.py`,
`alchemyui/app.py`, `tests/test_lab.py`

**Produces:**
- `workflows/lab.json`: eight prompts (`key`, `label`, `prompt`, `aspect`),
  looks, negatives and sampler pairs.
- `lab.expand(spec, reg, presets) -> list[Cell]`, which raises `LabInvalid`,
  caps at 96, and orders cells by checkpoint.
- `LabEngine(db, qm, reg, settings)` with `start()` (registers its listener
  and resumes live runs), `create_run(user_id, spec)`, `cancel_run(id)`,
  `run_public(id)` (cells, progress and tallies), `star(cell_id, stars)` and
  `adopt(cell_id, user_id)`. On preemption it requeues the cell as a new job.
- Routes under `/api/lab` (admin only): `GET presets`, `GET/POST runs`,
  `GET runs/{id}`, `POST runs/{id}/cancel`, `POST cells/{id}/star`,
  `POST cells/{id}/adopt`, `GET profiles`, `DELETE profiles?name=`.
- `GET /lab` serves `lab.html` to admins.
- Library: `/api/images` excludes `lab_run_id` rows and gains a `checkpoint`
  filter.

**Tests:** expansion counts, the cap, a bad axis or model is refused; a run
completes on FakeComfy, and each cell gets an image; the tally ranks starred
combinations; adopting writes the profile and cover, and the next resolve uses
it; a non-admin gets a 404; the Library does not show lab images; the
checkpoint filter works.
